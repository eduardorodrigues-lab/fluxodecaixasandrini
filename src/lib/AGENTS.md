- Known planned note parcels use remainingOverride.items[].note with stable IDs, document, condition and original/extended dates; zero-valued generic placeholders replaced by note detail are audited — preserves identification without duplicating forecasts.
- Form-only local envelopes are scoped by user, organization, real/simulation, form and record/new-draft ID; recovery clears review authorization and protects concurrent revisions — preserves filling without official autosave.
- Commit receipts contain the complete normalized server transition and a digest, applicable only to the exact version/context; all other outcomes reread — preserves concurrency and audited SQL snapshots without an optimistic success.
- Receipt reviews capture only receipt IDs from the existing scoped draft; legacy request IDs reconcile read-only before a new submission, and browser commit locks cover isolated/global sends — preserves other drafts and prevents competing confirmation packets.
- Entry detail adapts the clicked buildRows/computeFlow output without changing calculations; bank balances and transfer legs are separate read-only reconciliations — prevents rollovers, unused estimates and internal transfers from inflating consolidated cash.
- General flow ignores supplier/group preferences at the calculation boundary; other views keep their own filters — avoids invisible legacy recuts without clearing unrelated state.
- Manual confirmation recovery only reads the original request and reconciles with an explicit confirmed version; local rejected flags permit new review only with a persisted definitive failure/conflict phase — prevents legacy UNKNOWN packets from enabling duplicate writes.
- Timed-out submissions retain their original response during bounded read-only recovery and stop later polling after confirmation; complete transitions normalize with structural sharing — avoids false unknown states and full-document comparison without weakening audit/version checks.
- Audit history (~18 MB with changes) is never part of the normal load or save: screens/panels request it through `useAuditHistory(enabled)`, saves only mark it stale; large server reads use the service client only after `myOrg` validated membership for that exact org — keeps saving fast without weakening RLS or authorization.
- A form's reviewed payload is frozen only after the store captured it (phase/submittedAt); pre-capture rejections drop it so the next confirmation re-prepares from current fields. Explicit resend reuses the same requestId/ops after a not-found consult — idempotent in `commit_official`.
- Plan-wide loops call `distributePlanned` with `committedByCode(...).get(code)` instead of all titles, and hidden Lançamentos report tabs receive the base seen while visible — identical results without O(plans × titles) recalculation after every save.
- An operation whose server ACK is verified counts as saved for its form even if the screen refresh fails; form drafts already contained in the current base are dropped on restore — prevents saved edits from resurfacing as unsaved.
- A recovered unconfirmed packet gets one automatic read-only consultation per requestId and the strip shows that requestId — reconciles lost acknowledgements and enables audit correlation, never resends.
- Drafts/pending packets/form drafts are keyed by `params.baseGeneration`; older generations stay stored, never rehydrated — prevents contaminating a replaced base.
- Banks use `bankOperation` and the shared isolated confirmation; only explicitly reviewed account IDs recover legacy drafts, and transfers/initial-balance transitions capture bank dependencies — prevents global second saves and concurrent balance changes.
